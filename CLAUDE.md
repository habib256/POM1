## Project Overview

Apple 1 emulator (Dear ImGui, MOS 6502 + display + keyboard + ACI cassette) plus expansion cards: Uncle Bernie's GEN2 HGR, P-LAB A1-SID (6581/8580), TMS9918, microSD (65C22+ATMEGA), **IEC daughterboard** (1541 drive on microSD's spare VIA pins), MODEM BBS (65C51+TCP), Terminal Card, A1-IO & RTC, Juke-Box, CodeTank, Rich Dreher's CFFA1, SWTPC GT-6144 + PR-40 (1976, Jobs' *Interface Age* mod), **Uncle Bernie's Extended ACI** ($C500 page). Linux / macOS / Windows / Web (Emscripten).

## Build & Run

```bash
./setup_pom1.sh             # one-time deps (Linux/macOS)
cd build && cmake .. && make
./run_emulator.sh            # runs from repo root
```

Windows: `setup_pom1.bat` + vcpkg + `cmake --build . --config Release`. `compile_commands.json` symlinked for clangd.

**Hermetic / offline configure:** point CMake at dependencies already present on
disk with `-DPOM1_IMGUI_DIR=/path/to/imgui` and
`-DPOM1_KLAUS_BIN=/path/to/6502_functional_test.bin`. The Klaus fixture is
SHA-256 verified; if neither a valid local file nor the network is available,
configuration continues and only `klaus_6502_functional` is omitted from the
CTest inventory. `imgui_pin_sync` also supports source archives without `.git`.

**`imgui/` is NOT vendored** — it is `.gitignore`d, a local checkout each machine clones for itself (pin + the nine places it lives: see the **Docking** bullet below). `tools/ensure_imgui.sh` owns the acquisition logic; `setup_pom1.sh` and `packaging/raspberrypi/install.sh` both call it, `setup_pom1.bat` is its Windows twin, and CMake re-checks at configure time because a hand-made clone bypasses all three. It demands **two** things, and both are scars: the **docking branch**, because testing for the mere *directory* left every pre-docking clone in place until the build died hundreds of lines in on `ImGuiWindowFlags_NoDocking`; and **`IMGUI_VERSION_NUM >= 19290`**, because docking-ness alone lets an old docking tag through — `v1.90.x` has `ImGuiWindowFlags_NoDocking` but not `ImGuiChildFlags_Borders` (renamed upstream in 1.91.1, used by `src/bench/CodeBench.cpp`), and the Metal sampler patch is version-split at 1.92.7/1.92.8. A stale checkout is upgraded in place; a dirty or non-git one is refused untouched (dirtiness is `git diff --quiet HEAD` — `--porcelain` would count a Finder-dropped `.DS_Store` as a local change and dead-end the very repair it exists for).

**The development environment is optional — `-DPOM1_DEVTOOLS=OFF`.** The HGR/TMS paint + sprite editors, the beeper SFX editor, the SID tracker, the DevBench and the BASIC compilers are a *second product* sharing this process: ~18 300 lines that were built, ported (Linux / macOS Metal+GL / Windows / WASM / Pi GLES / kiosk PGO) and released on the emulator's schedule, so a regression in a paint editor blocked an emulator release. The option (ON by default, so nothing changes unless you ask) drops them from the target; the emulator itself is complete either way — only the tooling windows and their menu entries go, plus the chooser's *Create* / *Develop* columns and its Studio row, which become a 2-column chooser. The list is `POM1_DEVTOOLS_SOURCES` in `CMakeLists.txt` (ImGuiColorTextEdit is in it: `bench/CodeBench.cpp` is its only consumer), the macro is `POM1_DEVTOOLS` in `src/POM1Build.h` (CMake defines `POM1_BUILD_NO_DEVTOOLS`, same shape as `POM1_BUILD_GLES` → `POM1_GL_ES`), and `tests/CMakeLists.txt` does not even declare the 28 devtools tests in an OFF build — the two ends of the same partition as the `ctest -L emulator` lane. **The include directories are off the target too**, so an editor include that escapes its `#if` fails to compile rather than quietly pulling 87 files back in. Reference sites: **four** `MainWindow_*` files, 16 include edges, all pinned by `architecture_check`. What made that number small is that the editors were already portable modules behind host seams (`IHgrPaintHost`, `ITmsPaintHost`, `IBenchHost`) — the option is the harvest of that discipline, not a refactor. Measured on macOS/Metal, fresh tree, `-j8`, tests off: **149 → 104** translation units, **4.13 MB → 2.86 MB** of binary (−31 %), **27 s → 20 s** of build. Those are the numbers TODO.md's packaging decision was waiting on.

**Warnings & sanitizers.** POM1's own sources compile with `-Wall -Wextra` (`/W4` on MSVC), applied **per source file** — Dear ImGui and ImGuiColorTextEdit are compiled into the same executable and are not ours to keep clean; `src/third_party/{stb,ImGuiColorTextEdit}` are SYSTEM include dirs, and `stb_image_write.h` additionally needs the local pragma block in `main_imgui.cpp` because it is included by relative path through `POM1_SRC_DIR` (GCC classifies a header by where it *resolved* it, not by name). The tree was brought to **zero warnings** when the flags went in, so `-DPOM1_WERROR=ON` — CI only, never a local default — starts clean; it is set on the **Linux** job and on **macOS** since 23 août 2026 (AppleClang 17, both the Metal and the OpenGL configuration). **All five CI tiers now carry it** — Linux, macOS (Metal + OpenGL), Windows and WASM. The last two landed in septembre 2026 and both had been mis-diagnosed. **Windows**: MSVC `/W4` reports 134 distinct sites, 102 of them stb_vorbis (vendored, charged to `AudioDevice.cpp` which `#include`s the `.c`, silenced there plus `/wd4701` on that one file — 4700+ warnings are decided during code generation and no pragma reaches that point); the 30 POM1-owned ones are fixed. What held the flag off for three red CI cycles is C4244 raised inside MSVC's own headers — and the note that used to sit here **sent the search after the wrong one**. It said `std::fill<vector_iterator<uint8_t>, int>` in `<xutility>`, and that POM1 "contains no `fill(` at all, so the call site needs the instantiation backtrace rather than grep". Measured on a real Windows job instead: the diagnostic is **`<utility>(277)`, `std::pair`'s converting constructor** — `pair<uint8_t,uint8_t>::pair<int,int>` — and MSVC prints `see reference to function template instantiation` naming the caller two lines down. Two sites, both found by grepping `pair<uint8_t`: `tests/concurrent_frontends_smoke_test.cpp`'s `pokeSidRegisters({{0, 0x34}, …})` and `SidVoice.cpp`'s `silenceRegisters()` returning `{REG_V1_CR, 0x00}`. Both now spell the value `uint8_t{…}`. **The first is a TEST source** — `/W4` and `/WX` apply to the test binaries too, which is deliberate: they compile the same device sources the app does. The lesson worth keeping is about the note, not the warning: a diagnostic charged to a standard header still names its caller, and a claim that something "cannot be grepped" is worth re-checking before it costs a fourth cycle. (Six `std::fill` calls over `std::vector<uint8_t>` were given explicit `static_cast<uint8_t>` values while chasing the old note; MSVC never flagged them, but the casts match the five neighbouring `std::fill_n` calls and are kept.) **WASM**: five functions that only NATIVE paths call (`loadSizeFile`, `hexDumpFilter`, and three cc65 bundle helpers) were each defined unconditionally while their only callers sat inside a `#if !POM1_IS_WASM`; guarding the definitions closed it. The 11 lines those guards cost are what raised `mainwindow_lines` 16780 → 16791. MSVC's `/W4` was measured in septembre 2026: **134 distinct sites, 102 of them `stb_vorbis.c`** — vendored, and charged to `AudioDevice.cpp` because the `.c` is included there, so it needed the same `warning(push, 0)` bracket GCC and clang already had (likewise `miniaudio.h`, including where `CassetteDevice.h` pulls it into every consumer). The 30 POM1-owned ones were fixed rather than disabled: explicit `static_cast` for the narrowings, four renames for the shadows, `inet_ntoa` → `inet_ntop`. **One shadow was a live defect** — `hgr_convert_smoke_test`'s letterbox block declared a 100×192 local `img` and then handed the converter the outer 280×192 one, so it tested letterbox bars on a source that has none. `-DPOM1_SANITIZE=address,undefined` (or `=thread`) instruments **every** target including vendored code, forces LTO off, and is what the nightly CI job builds; `-DPOM1_FUZZERS=ON` is the other nightly (`ci.yml` → `fuzz`), which rebuilds the four `*_fuzz` targets behind `LLVMFuzzerTestOneInput` with clang and lets libFuzzer drive them for 15 min each over a **cached corpus seeded from the shipped files** (the ~120 hex dumps, the cassette recordings, a `.d64`, and a snapshot taken from a live headless run). It needs clang — Apple clang and g++ ship no libFuzzer, which is why the deterministic driver is the DEFAULT rather than the fallback: a fuzz-only gate would silently not run for most contributors. A finding fails the job and uploads the input as an artifact, and that file is the deliverable — it becomes a case in the matching `*_smoke` test, the way every defect these targets have already found did; `tests/CMakeLists.txt` scales every declared `TIMEOUT` ×5 under it, because the two Applesoft tests boot a whole interpreter on the emulated 6502 and blow a 120 s budget under ASan while finding nothing — a false red is worse than no job.

**Graphics backend:** `POM1_RENDERER` cache option picks `opengl` or `metal`. Defaults: **Metal on macOS-non-WASM**, OpenGL everywhere else (Linux, Windows, WASM). Override with `cmake -DPOM1_RENDERER=opengl ..` for the legacy macOS GL path; selecting `metal` outside Apple is a hard configure error. Single seam in `src/PomRenderer.h` (the `pom1::renderer()` singleton fronts both backends — no direct `gl*` calls outside `PomRenderer_GL.cpp` / `PomRenderer_Metal.mm`). macOS CI builds both configurations and runs the preset-first-cycle, live-topology and non-silent audio gates from each build tree. WASM boots under headless Chromium; `pom1_wasm_machine_probe` + `pom1_wasm_measured_cpu_hz` prove preset/RAM/Monitor/PC/CPU activity before the smoke accepts the non-black WebGL2 frame.

**GL tier — `POM1_GL_ES` (`src/POM1Build.h`):** orthogonal to the backend choice above. It says *"we speak GLES"*, **not** *"we are a browser"* — the distinction the old `__EMSCRIPTEN__` guards conflated. On: always under WASM (WebGL 2.0 **is** GLES 3.0), and natively via `cmake -DPOM1_GLES=ON` (**Raspberry Pi 4/5** — Mesa's V3D caps *desktop* GL at 3.1, so the default GL 3.2 core request fails outright; also most ARM SoCs / old iGPUs). POM1's GL usage (VAO/VBO, shaders, FBO, 2D textures) is the common subset of GL 3.2 core and GLES 3.0, so **one set of sources covers both** — only four things differ, all keyed on `POM1_GL_ES`: the header (`<GLES3/gl3.h>` vs `<GL/gl.h>`+`GLProcs.h`, plus `GLFW_INCLUDE_ES3` in `PomRenderer_GL.cpp`), the `#version 300 es` + precision prologue (`OpenGLShader.cpp`), **direct** entry points instead of the lazy `glfwGetProcAddress` slots (libGLESv2 exports them; same branch as macOS), and the GLFW hints (`GLFW_OPENGL_ES_API` + `GLFW_EGL_CONTEXT_API` — GLX can only hand out a GLES context where `GLX_EXT_create_context_es2_profile` exists, which V3D lacks). Native GLES links `GLESv2`+`EGL` instead of `libGL`; `-DPOM1_GLES=ON` with `POM1_RENDERER=metal` or under Emscripten is a hard configure error. CI compiles the four affected TUs on every push (`ci.yml` → "GLES 3.0 tier"), since the release job that ships it is tag-only. **Two shipped GLES packages, deliberately different**: `release.yml`'s `raspberry` job builds a **generic** aarch64 AppImage (must run Pi 3 → Pi 5), while `pi-borne.yml` (manual dispatch, ported from NeoST) builds for **one core** (`-mcpu=cortex-a72` = Pi 4/400) with two-pass PGO + LTO and emits both an AppImage and a kiosk `tar.gz` — see `packaging/raspberrypi/{build_in_bookworm_pi.sh,README.md}`. Both build inside a `debian:bookworm` container, never on the `ubuntu-24.04-arm` runner: Pi OS *is* bookworm (glibc 2.36) and the runner would stamp `GLIBC_2.39`, which starts on no Pi.

**Desktop-GL fallbacks (the GLES tier is preferred, these are the net).** Nothing hardcodes `#version 150` any more, so a *desktop-GL* build now survives a sub-3.2 stack: `main_imgui.cpp` retries context creation **3.2 core → 3.2 → 3.1 → 3.0**; `PomRenderer_GL.cpp`'s `imguiGlslVersion()` steps the ImGui preamble **down** to what `GL_SHADING_LANGUAGE_VERSION` reports (150 → 140 → 130, never up, GLES strings untouched); `OpenGLShader.cpp` picks the CRT dialect the same way but *by actually compiling* each candidate — a driver can advertise a version and refuse it in that context, and the failed attempts must stay silent AND clear `errorOut`, or the CRT panel says "shader unavailable" over a working stack. Both shader sets only need GLSL 1.30 (`in`/`out`, `texture()`, `fwidth()`); Mesa's V3D caps desktop GLSL at **1.40**, which is what used to kill the CRT effects on a Pi. Startup traces: `[CRT] GLSL 140 (driver: 1.40)`, `[GL] ImGui shaders: #version 140 instead of #version 150`. Keep any new shader body inside GLSL 1.30 or the cascade is a lie. `option(POM1_LTO)` (ON) exists so a ≤2 GB box can link at all.

**WASM:** `source emsdk_env.sh && emcmake cmake .. && emmake make && emrun POM1.html`. MEMFS preloads `roms/ fonts/ software/ sdcard/ cassettes/ cfcard/cfcard.po` (other `.po` are desktop-only, >140 MB) — **`pic/` is NOT preloaded** except `icon.png` + the cassette-deck logo: every other photo is fetched over HTTP on first window open (`ensurePicFetched` in `MainWindow_Dialogs.cpp`, tri-state Ready/Pending/Failed where Pending must not set the caller's `loadTried`), served from the `pic/` dir that `tools/assemble_wasm_site.sh` publishes next to the page. `emrun` from a bare build dir therefore shows "not found" in photo windows unless a `pic/` copy sits beside `POM1.html`. Rebuild after any change under those trees or `build-wasm/shell.html`. The `sketchs/` + `dev/` staging copies are **deny-lists** (`file(COPY … REGEX … EXCLUDE)`, excluding heavy media + build residue), never allow-lists: the desktop packagers ship the whole trees, so an allow-list makes any newly-introduced extension vanish from the *web build only* — silently, in the one build nobody runs locally (that's how `sketchs/logo/*.logo` went missing from `POM1.data`).

**cc65:** per-project Makefiles call `ca65`+`ld65`, then `python3 emit_*_txt.py` lands `.bin`+Woz-hex `.txt` under `software/<dir>/`. `make -C dev/codetank` is the CI gate. Linker configs in `dev/cc65/`. The gen2c runtime is split into per-family C modules (`gen2_init.c`, `gen2_pixel.c`, `gen2_rect.c`, `gen2_text.c` + `gen2_text_num.c` (glyph core vs number formatters — numbers pull rect/hex/soft-mul, strings don't), `gen2_sprites.c`, `gen2_preshift.c`, `gen2_sprengine.c`, `gen2_geom.c`, `gen2_lores.c` — see `dev/lib/gen2c/gen2c.mk`) so ld65 dead-strips per family; hot paths stay in `gen2_blit.s` (+ the masked save-under sprite kernels in `gen2_sprmask.s`), which any project linking those modules must also assemble.

## Architecture

All C++ sources under **`src/`** (vendored deps in `src/third_party/`). `imgui/`, `tests/`, `tools/` stay at repo root. File references below are bare basenames — find them under `src/`.

### Parmigiani's golden rule — "one board at a time"

Claudio PARMIGIANI (P-LAB designer): on real hardware exactly ONE P-LAB card is plugged. The 6502 bus has no arbitration and many P-LAB cards overlap windows (A1-SID `$C800-$CFFF` vs TMS9918 `$CC00/$CC01`; A1-IO RTC `$2000-$200F` vs GEN2 HGR `$2000-$3FFF`; Juke-Box claims `$4000-$BFFF`; microSD's Applesoft Lite RAM window `$6000-$7FFF` vs CodeTank `$4000-$7FFF` — plugging either evicts the other, TMS9918 host stays). POM1 **breaks this on purpose** in the "Multiplexing Fantasy" preset — fantasy, not buildable. Mutex rules elsewhere mirror real bus conflicts. When adding a card, honour the rule and document any intentional coexistence.

### Core layers

- **M6502** (CPU). `op = quint16`, `tmp = int` (carry/borrow via bit 8). BCD ADC propagates low→high carry from `(A & 0xF0)`, not the unadjusted sum. `run(maxCycles)` **returns actual cycle count** (overshoot up to 6) — wallclock pacers must deduct. 24-slot PC control-flow-edge ring + `dumpPcTrace(tag)`. `setTestMode(true)` = flat 64 KB for the Klaus harness only. **At most one interrupt per instruction boundary** — NMI takes priority over IRQ (7 cycles, 3 bytes pushed); never both. **Undocumented multi-byte opcodes advance PC by their real NMOS operand length** (`Unoff2`/`Unoff3` dispatch + matching disassembler addressing mode, mnemonic `???`) — never the no-op 1-byte fallback that desynced the stream.
- **CpuClock.h** — `POM1_CPU_CLOCK_HZ = 1 022 727` (14.31818 MHz ÷ 14). Single source of truth.
- **Memory** — 64 KB. Owns every peripheral (`unique_ptr` + enable flag). MMIO dispatched via **`PeripheralBus`**; `memRead/memWrite` only handle PIA `$D0xx` aliasing, ROM write-protect, OOR strict mode, the cassette write-sniffer, `DisplayDevice::onChar` + TerminalCard hook, then raw `mem[]`. **Redundant-ROM-load guards**: on the microSD Applesoft Lite path, skip the **Woz Monitor** reload when `mem[$FF00..$FF01] == D8 58` (Woz Monitor's `CLD`/`CLI` signature — Applesoft Lite itself at `$6000` always loads); skip SD CARD OS reload when `mem[$8000..$8001] == A9 00`.
- **PeripheralBus** — central MMIO dispatch. Peripherals register `(name, range, priority, onRead, onWrite)`. O(1) hot path via `pageMask[256]` bitmap. `std::stable_sort` by priority — TMS9918 wins over SID at `$CC00/$CC01` via priority 10. `onWrite = {}` → pass-through to RAM; explicit no-op = block (CFFA1 ROM). **A handler that writes `mem[]` itself must call `Memory::isRomWriteProtected(addr)` first**: `bus.tryWrite` answers at the TOP of `memWrite`, so its own ROM guard never runs. GEN2's soft-switch handler spans `$C200-$C7FF` (scattered mirrors) and falls through to flat RAM for what it doesn't decode — which swallowed the extended ACI PROM at `$C500` (A9 = 0 there, so the decoder is blind to it) and made that page writable the moment the HGR card was plugged. Pinned by `extended_aci_smoke` part A.
- **Card identity foundation** — `CardTypes.h` owns the stable, append-only
  `CardId`, allocation-free `CardSet`, and `CardDescriptor`. Descriptors live
  directly in `Memory::cardSlots()`—the existing load-bearing snapshot
  registry—so topology work must extend that registry rather than introduce a
  parallel card table. The two FLAGS-only modes use `CardId::Invalid`; Extended
  ACI has a descriptor-only row with no flag/section because its legacy state
  remains in `MEM`. Every real row declares its CPU address ranges,
  capabilities, dependencies, incompatibilities and optional variant group;
  `BusConflicts.h` uses `CardId` rather than display-name strings. A
  daughterboard requirement is deliberately not a conflict, while overlapping
  cards resolved by bus priority remain coexistence rather than exclusions.
  `card_registry_smoke` pins complete/unique IDs and keys, snapshot-tag
  agreement, valid ranges, dependency facts, conflict-table equivalence and
  symmetry, variant groups and `CardSet` semantics.
- **Card topology policy** — `CardTopology.{h,cpp}` is allocation-free pure
  policy over `CardSet`: it reports active conflicts, gates a candidate and
  deterministically resolves a requested set. `TopologyMode::Fantasy` permits
  multiplexing; Strict additionally rejects the SID/TMS9918 overlap that the
  fantasy bus can arbitrate by priority. The Silicon Strict UI consumes this
  API by `CardId` and contains no card-name comparisons or conflict table.
  `card_topology_smoke` pins both modes, every declared conflict, survivor
  priority, dependencies, transitive daughterboard removal and idempotence.
  Public `Memory::setXxxEnabled()` methods remain compatibility entry points,
  but obtain attach/detach decisions from `planCardToggle()`; they now own only
  hardware effects such as bus handles, ROM mirrors, audio sinks and resets.
- **Named preset configuration** — `PresetId` is stable and index-compatible
  with all 13 historical layouts; `kDefaultPresetId` names the shipped default
  explicitly. `MachineConfig` stores cards in one `CardSet`; Juke-Box and
  CodeTank settings use named option structs, and Krusader remains a separate
  ROM-payload flag because it is not a card. Consumers use `enabledCards()` /
  `hasCard()`. `validateMachinePresets()`
  checks enum/table cardinality, daughterboard closure and Strict conflicts;
  the CLI smoke test executes it and pins the exact card set for all 13 IDs.
- **Whole-card transitions** — `CardTopology::planConfiguration()` closes
  dependencies, rejects the entire Strict request on any resulting conflict,
  and returns allocation-free deterministic detach/configure/attach arrays.
  Reverse CardId order detaches daughters before hosts; forward order attaches
  hosts first. `EmulationController::applyCardConfiguration()` executes the
  full plan under one `stateMutex` acquisition and publishes once, including
  option configuration between hardware phases; validation rejection mutates
  nothing. The headless preset path uses this façade. The delayed GUI plug path
  and its CLI/Bench overrides remain compatibility consumers of individual
  GUI deferred card changes now travel as one `CardConfigurationRequest`;
  `MachineCoordinator` applies its `TransitionPlan`, while
  `EmulationController` owns the state lock and single snapshot publication.
  Cassette preload remains on its independent timing rail.
  This adds one intentional direct `Memory.h` consumer (architecture fan-out
  baseline 57 → 58) while removing the executor from the controller; do not
  grow that edge further when adding application commands. **58 → 59** is
  `hermetic_core_smoke`, a TEST: the fan-out metric counts `tests/*.cpp` on
  purpose, and a test whose subject is "what does constructing a `Memory`
  touch?" cannot be written without including it. That is the only kind of
  raise this ceiling takes — never one that buys an application-layer
  shortcut.
  Single-card UI/CLI changes use `EmulationController::setCardEnabled(CardId,
  bool)`; all fifteen per-card `setXxxEnabled()` controller wrappers are gone.
  `card_registry_smoke` executes the daughterboard cascades and representative
  SID/Juke-Box exclusions through the real coordinator.
- **The UI's staging rail — `StagedCardConfiguration.h`.** `request.cards` is an
  **ABSOLUTE** target set: `MachineCoordinator` detaches every card the request
  does NOT name, so the DTO alone cannot tell *"nothing staged"* from *"stage
  the empty machine"*. The GUI needs that distinction because
  `performMemoryLoad()` and six DevBench paths commit up front to flush a
  preset's plugs before the CPU runs, and `applyMachineConfig()` has usually
  committed already — the unguarded repeat applied the empty topology and swept
  **every card off the bus**. That is what silently broke BBS auto-dial: loading
  `software/NET/bbs.*.txt` unplugged the Wi-Fi modem microseconds before the
  program at `$0280` started writing to the ACIA at `$B000`, so it dialled into
  RAM. `pom1::StagedCardConfiguration` carries `pending()` alongside the request
  and is **pure value logic** (no ImGui, no GLFW, no `Memory` — same seam rule as
  `Apple1KeyMap`/`WindowGeometry`, pinned by `staged_card_configuration_smoke`).
  Two rules it enforces: an untouched transaction commits **nothing**, and the
  **first** `stage()` seeds cards *and* board options from the LIVE machine so an
  amend (*"also plug the TMS9918"*, the chooser launchers, a DevBench cart swap)
  adds to what is on the bus instead of replacing it with a single-card machine —
  `applyMachineConfig()` still assigns `cards` wholesale over that seed. `clear()`
  resets everything **except `mode`**, the only carrier of Strict-vs-Fantasy (the
  machine stores no topology mode). Every write to the staged request goes
  through `MainWindow_ImGui::stageCardConfiguration()`; there is no headless
  equivalent — `applyHeadlessConfig()` builds one request and commits it once.
- **Peripheral lifecycle (phase 2, incremental)** — `Peripheral` tracks
  `Constructed → Attached → Reset → Active`; transitions are idempotent and
  skipped phases fail. `MachineCoordinator` owns attach/detach markers and
  marks `Reset` only after the real peripheral reset passes used by hard reset
  and clear-memory, then promotes ready devices to `Active`. ACI is special:
  it stays `Reset` until its independent cassette source is actually registered
  with the mixer, and returns to `Reset` when that source is removed. Deferred
  GUI finalization attaches cards before cassette activation/preload.
- **EmulationController** — façade over CPU + Memory + emulation thread, implemented across **4 TUs** since the août-2026 god-file pass (207 method definitions used to sit in one 2143-line file): `EmulationController.cpp` (CPU thread, run/stop/reset, step + step-over, breakpoints/watchpoints/PC-trace, key injection, memory + peripheral pokes, the slice/pacing loop — the pacing constants stay here because the loop is their only user), `_State.cpp` (memory images, snapshots, rewind, ROM re-loads), `_Machine.cpp` (silicon-fidelity + diagnostic knobs), `_Cards.cpp` (cassette/audio + the per-card passthroughs). The split is **pure code motion** — no signature and no call site changed. **Mutex order applies to every TU**: `stateMutex > rewindMutex > keyboard.keyMutex > publisher.snapshotMutex` (ranks 30/25/20/10 in `LockOrder.h`, pinned by `lock_order_smoke`). **Rewind capture is split across the two outer locks**: the slice copies the state under `stateMutex` (`saveSnapshotToBuffer`), releases it, then delta-encodes under `rewindMutex` alone; a `rewindGeneration_` bump by any timeline edit (enable/clear/resume-here truncation) retires a blob staged before the edit so it is never appended as a stale future frame. `stateMutex` is a `PriorityMutex` (MAX speed yields on `hasWaiters()`). Slice cap: 6000 cycles desktop, 50 000 WASM (single-threaded). Native = dedicated thread; WASM = `pumpEmulationMainThread()`.
- **Snapshot restore is all-or-nothing — validate, then apply.** `Memory::loadSnapshotFromBuffer` runs `pom1::validateSnapshot()` (pure, `SnapshotIO.h`) over the bytes before a single byte of machine state moves, and `Memory::loadSnapshot(path)` now reads the file through `pom1::readFileBounded()` and **delegates to the buffer path**, so a file and a rewind blob get the same gate — streaming straight from disk would have skipped it, and the file path is the one that sees files POM1 did not write. The gate covers the file's SHAPE (truncation, forged lengths, MEM's fixed length, GEN2VID's count-then-elements journal) but cannot vouch for a **card's** payload — that grammar lives in the card's own `deserialize`, and several of them restore fields before they can reject what follows (`PR40Printer` has written its mode, FIFO and four counters by the time it validates the paper-roll line count). So the apply pass is wrapped in a **rollback**: `loadSnapshotFromBuffer` keeps a copy of the live machine and puts it back if the restore fails. Measured before adopting it — serialising costs **16 µs** against the **452 µs** a restore already takes, i.e. 3.6 %, which buys all-or-nothing semantics against *any* failure including a card throwing; the rewind seek path pays it too and does not notice. Forging that PR-40 count used to leave the machine holding the snapshot's CPU **and** RAM while the caller was told the load had failed. **`pom1::readFileBounded()` (`FileBytes.h`) is the one place that reads a whole file for a parser** — memory images, cassette containers and snapshots all go through it, and it checks the size **before** reading, because slurping the file IS the allocation the limit exists to prevent.
- **SnapshotPublisher** — SPSC slot, page-level dirty copy (1 bit per 256 B page, contiguous runs → single memcpy). Idle Wozmon = zero copy. TMS9918's 16 KB skipped when unplugged.
- **RewindBuffer** — **recording is OFF by default**; CPU → State Rewind opens the dedicated control window. The toolbar timeline was removed because capture serialises ~80 KB 4×/s under `stateMutex` and the always-visible control overloaded the main menu. Budget derived from host RAM by `defaultRewindBudgetBytes()` (~1/16 physical, clamped to [16 MB, 128 MB]; any host ≥ 2 GB lands on the historical 128 MB ceiling, an unreadable probe falls back to it rather than shrinking silently). microM8-style timeline; operates on snapshot blobs (`Memory::saveSnapshotToBuffer`, same byte layout as the `.snap` file). KEYFRAME + DELTA frames anchored in segments; eviction drops whole leading segments past the budget (128 MB default). Touched only under `rewindMutex` (the UI paths take it inside `stateMutex`). Pinned by `rewind_buffer_smoke`.
- **ResourceLocator** (`src/ResourceLocator.{h,cpp}`) — **one** search order for POM1's data (`roms/`, `sdcard/`, `disks/`, `cfcard/`, …). Only the executable-derived half is cached. An **absolute** path is returned as given, never rewritten — `--iec-disk /tmp/x.d64` and the file pickers come through here. `Memory` takes a locator (defaulted) and **keeps** it, so `loadROM` consults it on every preset switch; `ResourceLocator::rootedAt(dir)` is how a caller says "look ONLY here", which is now the only way to mean "no ROMs anywhere" — chdir'ing away no longer suffices, since the binary itself sits in the tree. `pom1::executableDirectory()` is a deliberate second copy of `bench::executableDir()`: `src/bench/` stays standalone for POM2, the same rule that has `CodeBench.cpp` repeating the hex-dump extensions literally. **Every consumer now routes through it** — the 52 hand-rolled probes that survived the class's introduction (UI, dialogs, presets, DevBench, the editor hosts, `GraphicsCard`, `Screen_ImGui`) are gone, and with them two things worth naming: `findIniDefaultsFile` was a full second copy of the search order (four cwd prefixes, then `executableDirectory()` + `Resources/` + `share/POM1/`), and the **next-to-the-exe half of four photo/font lookups existed only under `#if defined(_WIN32)`** — so a Linux or macOS build launched from outside the tree silently showed no icon, no Font Awesome and no photos. Five `"../` literals remain in `src/` and none is a probe: MicroSD's guest-side traversal guard, and the "parent directory" row of the four portable editors' file browsers. **`tools/check_resource_probes.py` (ctest `resource_probes_sync`) fails the 53rd** — fourth guard of the `version_sync` / `imgui_pin_sync` / `doc_paths_sync` family, because this drift never returns all at once, it returns one locally-reasonable call site at a time.

- **Extended ACI** — Uncle Bernie's improved Gen-2 cassette interface (Applefritter, august 2026). **No new MMIO**: a second 256-byte PROM page at `$C500-$C5FF` beside Woz's untouched `$C100` firmware, still driving the same `$C000` flip-flop / `$C081` comparator. `C500R` relocates the stock ACI ROM into the **stack page** (`$0100-$01FF`), patches the RAM copy's `R`/`W` branches to an `RTS` and re-vectors its two `JSR $C1F1` to `$C5F1` — which both installs the Apple-II-style checksum accumulator *and* retires the copy's own `$01F1-$01FF` tail, freeing exactly the bytes the relocated code needs for a stack (SP starts at `$FF`). That is why the page cannot be relocated or trimmed: touch either patch and the firmware overwrites its own stack. - **IEC daughterboard** — no new MMIO; piggybacks on microSD's VIA PORTB bits 2-6 (SN7406 inverters). Wired-AND open-collector in `IECBus`; virtual 1541 in `Drive1541` backed by 174 848 B `.d64` files. Enabling IEC cascade-enables microSD. **A D64 is a LINKED structure** — every directory block and every file sector names the next one, and *nothing anywhere records how long a chain is*; you find out by following links. So every walk in `D64Image` uses **cycle detection** (`VisitedSectors`, 683 bits), never a hop counter: the counters it replaced were guesses wrong in both directions — the file walk allowed 1000 hops on a disk holding 683 sectors, so a self-linking sector yielded a 254 KB "file" out of a 174 KB image, while the directory walk allowed only 256, fewer than the 683 blocks a pathological but **legal** directory chain could occupy. The BAM's per-track free counts are likewise clamped to the geometry rather than believed (an all-`$FF` disk reported 8670 blocks free on a 664-block disk). `mount(path)` reads through `pom1::readFileBounded()` and delegates to `mountBytes()`, so a file and a buffer share one set of acceptance rules — and the format is reachable from a fuzzer without a disk on disk.
- **SID** — wraps libresidfp (GPL-2.0+, vendored). **The chip is built on first use by the private `Memory::sidChip()`, never by `Memory`'s constructor** — libresidfp computes its filter tables there, ~120 ms for the FIRST chip in a process (0.46 ms for each one after it), which was 96 % of the runtime of every test binary holding a bare core; 60 of the 68 test files that name `Memory` construct one and exactly two plug the card. Every access goes through `sidChip()` (`getSID()`, both bus lambdas, `advanceCycles`, the snapshot's card accessor) so no caller can observe a null `sid`, and the snapshot format is unchanged — the "A1-SID" section is still always written. `std::call_once` because the UI and emulation threads can both be first to ask. **The cost MOVED rather than vanished, on purpose**: `EmulationController`'s constructor warms the chip **before any lock** and before the emulation thread exists, because every site a frontend would first touch it from holds `stateMutex` (`SnapshotPublisher` reads the chip model on every publish; `MachineCoordinator` attaches the card during a topology swap) — paying 120 ms there parks the audio callback and the render thread for the duration, which is exactly what `concurrent_frontends_smoke`'s 100 ms `maxStateHoldNs` gate caught on the first cut. Cycle-driven, SPSC ring (4096-cycle chunks → 16 384-sample ring, drop-newest on overflow so producer never touches `ringTail`). `chipMutex` serialises register writes / `clock` / `setChipModel`. **WASM**: 4 MB stack (`-s STACK_SIZE=4194304`) — filter tables overflow default 64 KB; filter builders run sequentially under `__EMSCRIPTEN__ && !__EMSCRIPTEN_PTHREADS__` (~50 ms cold start).
- **TerminalCard** — TCP loopback :6502 (IPv6 `::1` refused). **The listener follows the PLUG, nothing else.** It used to be opened from `reset()`, unconditionally — and `Memory::resetMemory()` resets every card regardless of enablement — so every POM1 process and every test binary bound `:6502` with the card **unplugged**, which is its default. A second core in the same process warned `failed to bind port 6502 (already in use?)`, and `terminal_card_smoke` had to skip `reset()` altogether ("doing so would make it fight a POM1 instance the developer has running"), pinning the firmware defaults off the constructor's member initialisers instead of off the reset that actually restores them. `TelemetryPort` next door had always opened its server only when enabled; `TerminalCard::setEnabled()` brings this card in line, `Memory::setTerminalCardEnabled()` drives it, and `reset()` re-listens only when plugged. 7-bit and 8-bit raw modes. `Ctrl-S` / `ESC S` arms a screenshot; main render thread calls `PomRenderer::readBackbufferRGBA` between `renderDrawData` and `present`, writes `screenshots/pom1_latest.png` (GL backend does `glReadPixels` + Y-flip, Metal backend blits the drawable to a shared-storage staging texture + swizzles BGRA→RGBA; both return top-down RGBA8 so the writer is renderer-agnostic). Result string uses `screenshotResultMutex` (render thread never blocks on `cardMutex`). Desktop only.
- **WiFiModem** — 65C51 + ESP8266 AT emulation, TELNET IAC filtering, non-blocking TCP. Desktop only; WASM stubs return `NO CARRIER`.
- **TelemetryPort** — **not a card**: a dev-only virtual side channel at `$C440-$C443` for automated game testing (binary frames out, synthetic input in, optional lock-step where an end-frame write parks the CPU until the harness ACKs). Lives in the `$C4xx` **A9=0 dead zone** GEN2's decoder (`SEL = $Cxxx & !A11 & A9 & A4`) is structurally blind to, and registers at **priority 30** so it owns its four bytes over GEN2's `$C200-$C7FF` pass-through. Off unless `--telemetry-port` arms it. Protocol → [`doc/TELEMETRY_SIDE_CHANNEL.md`](doc/TELEMETRY_SIDE_CHANNEL.md).

- `applyPendingLayout()` runs before `Begin()` with **`ImGuiCond_FirstUseEver`**. **Widgets must not call `SetNextWindowSize(..., FirstUseEver)`** — overrides preset. `SetNextWindowSizeConstraints` is OK.

Every entry into a fullscreen layout must arm it — the four sites are the `render()` transition, `applyMachineConfig` (no saved size), `loadPresetLayout` (both the `.size`-present and the `.size`-missing paths) and `resetActivePresetLayout`; the last one must also drop the `Apple 1 Screen` entry from `pendingLayout`, since a reset force-applies with `ImGuiCond_Always` *after* the expand's `SetNextWindowSize` and would stamp the windowed rect back over it. Everything keyed on "does the window fill the screen?" must call `MainWindow_ImGui::osWindowIsFullscreen()` — **not** the `fullscreen` member, which misses macOS' native fullscreen space (GLFW models only its own; the Cocoa seam is `src/MacNativeFullscreen.{h,mm}`, compile-time `false` off macOS). Resizing a window inside an AppKit fullscreen space is silently ignored, so the old code shrank the layout while the frame stayed screen-sized. ### MMIO

- `$D010` (KBD) — last key with bit 7 set; read clears strobe.
- `$D011` (KBDCR) — bit 7 = 1 when key ready.
- **PIA register banking** — each port hides TWO registers behind one address, selected by **bit 2 of its control register**: clear → the **data direction register**, set → the peripheral (data) register. `$D010` KBD/DDRA + `$D011` CRA; `$D012` DSP/DDRB + `$D013` CRB. **POM1 seeds the POST-reset state** (`CRA=CRB=$A7`, `DDRB=$7F`, `DDRA=$00`) rather than the silicon's all-zero power-on, and this is **load-bearing**: POM1 jumps straight into programs (`--run`, DevBench Run, `jumpTo`) without executing the Monitor's reset at `$FF00`, and a zeroed CRB leaves the DDRs banked in — the Monitor's own ECHO then writes its characters into DDRB and **hangs forever** on its `BIT $D012 / BMI` as soon as one with bit 7 set lands there (that is exactly what blanked the GEN2 golden frame while this was being built). `$D011` reads keep their historical semantics (bit 7 = key ready, nothing else) — every program tests it with BIT/BPL and modelling CRA read-back would change every read in the corpus for no caller. **The four shadow registers ride in the snapshot's `MEM` section (v6+)** and must stay there: they are NOT reconstructible from the 64 KB image — `memWrite` returns *before* the `mem[]` store when a DDR is banked in, so DDRA/DDRB never appear there at all, and although CRA/CRB are mirrored, every READ answers from the member. Leaving them out made a restore (and every rewind scrub, which replays the same blobs) inherit the *live* machine's banking. A pre-v6 blob restores the post-reset seed, never a reconstruction from `mem[$D011]`/`mem[$D013]` — those are 0 on a machine that never ran the Monitor's reset, i.e. exactly the hang above. Pinned by **`pia_ddr_smoke`** (§8 is the round-trip); **`extended_aci_smoke`** part C is the end-to-end proof, since Uncle Bernie's Codebreaker probes DDRB (`CRB:=0` / read `$D012` / expect `$7F`) and prints *"I WANT TO RUN ON A REAL APPLE-1 !"* when an emulator gets it wrong.
- `$D012` (DSP) — write triggers display callback + busy-counter except **raw `$7F`** (WOZ Monitor's reset-time `LDY #$7F / STY $D012` DDR setup would paint a spurious `_`). Real hardware latches only on PB7=1; POM1 is permissive so emulator-era demos calling WOZ ECHO with bit 7 clear still render. `$DF` via ECHO still yields `_`. TerminalCard + PR-40 sniffers get every write unfiltered.
- PIA 6821 incomplete decoding aliases `$D0xx` → `$D010-$D013` by low 2 bits (all **four** registers — `$D0x3` is CRB, not RAM). `setKeyPressed` forces uppercase; `setKeyPressedRaw()` bypasses it (Terminal Card).
- **`Memory::configureResetVectors(addr)` only writes `$FFFC/$FFFD` (RES)**. NMI (`$FFFA/$FFFB`=$0F00) and IRQ (`$FFFE/$FFFF`=$0000) stay at the authentic WozMonitor.rom values so P-LAB programs installing an IRQ trampoline at `$0000` route correctly.

### Other gotchas

- **WAV and AIFF are parsed by POM1, not miniaudio — and the parsers live in `src/PcmFile.{h,cpp}`, pure.** `ma_decoder` covers MP3/FLAC (+Vorbis) and has no AIFF backend, but AIFF is what Uncle Bernie's `ACIace` tape synthesiser emits, so POM1 reads big-endian IFF by hand (COMM/SSND, the 80-bit extended sample rate, PCM 8/16/24/32 + AIFF-C `sowt`/`fl32`); the RIFF/WAVE reader is its little-endian twin. `parseWavPcm` / `parseAiffPcm` take **bytes and return mono float + rate + error/warning** — no device, no file, no log sink — and `CassetteDevice::loadPcmTape()` is the shared size-check-read-parse-decode body behind both `loadWavTape` and `loadAiffTape`. Traps they handle: AIFF PCM is **signed at every width** including 8-bit (WAV's 8-bit is unsigned — confusing them is a full half-scale DC offset the pulse decoder reads as one unbroken level); chunk sizes are compared against the bytes **remaining**, never `offset+size`, which wraps on wasm32; SSND's alignment offset must stay inside its chunk; COMM's frame count wins only when it is the **smaller** of the two; and `.aiff` takes the **pulse path unconditionally** like `.aci` — it is cassette DATA, never deck music, and audio-stream mode would carry no transitions for `$C081` to read. **Hardening:** `kMaxPcmFileBytes` (256 MB, checked before the file is read) and `kMaxPcmFrames` — the latter is not new, it is the thirty-minute cap `loadMiniaudioTape()` has always applied, whose comment says it "prevents accidental 2-hour podcast loads from chewing memory"; the two hand-rolled parsers had **no cap at all**, so exactly that case was refused as an `.mp3` and accepted as a `.wav`. `kMinPcmSampleRate`/`kMaxPcmSampleRate` bound a field the WAV parser did not bound at all, and whose low end made the downstream `deltaSamples × CPU_HZ ÷ rate` narrowing **undefined behaviour** (`pcmToDurations` now clamps in the double domain before narrowing, because miniaudio-decoded files reach it too). Non-finite samples in a float container become silence with a warning — every comparison against a NaN is false, so a corrupt float WAV used to read as a flat line and be reported as "no detectable cassette signal".
- **Audio is a service the core is HANDED, never one it builds — `pom1::IAudioService` (`src/AudioService.h`).** `Memory` used to `make_unique<AudioDevice>` in its constructor, so every core reached for the host's sound hardware on the way up, a test core included. `main_imgui.cpp` now owns the `AudioDevice` (GUI **and** headless) and passes it down through `MainWindow_ImGui` → `EmulationController` → `Memory`, which keeps a plain pointer and owns one only when nothing is injected. Three consequences, and each is the point of a different half of the change: **(1)** `--audio-latency` is a constructor argument instead of `AudioDevice::setPreferredLatencyMs`, a static whose only reason to exist was reaching across the gap between `main()` and a device built four layers down. **(2)** `Memory`'s `initializeAudioHardware` now defaults to **false**, because `Memory mem;` appears in 50 test files and every one of them opened a real OS sound device (~21 ms each, ~100 ms for the first in a process, plus miniaudio errors on a soundless CI box) to run tests that never listen. `EmulationController`'s flag follows for the same reason. **Measured by counting miniaudio's own open line across a full `ctest`: 161 → 0.** The frontends pass `true` explicitly, so nothing audible changed — `--audio-latency 120` still logs `output cushion 120 ms (1764 frames x 3 periods)`. **(3)** `~Memory` unregisters its sources (`removeSource` is a lifetime barrier): an injected service outlives the machine, so the member-declaration-order rule below is no longer the only thing between the mixer and a dangling `CassetteDevice`. `pom1::NullAudioService` is the in-memory double — no mixer, no scratch, no threads — and is **not** `AudioDevice(false)`, which still mixes and is what the audio tests use. Pinned by `hermetic_core_smoke` §4.
- **`AudioDevice::getActualSampleRate()` returns the miniaudio-negotiated rate** (44.1 kHz requested, often 48 kHz on Apple Silicon) — cycle-driven sources must use this or tempo drifts. WASM always 44.1 kHz.
- **The audio callback must not allocate and must not wait on slow work.** `AudioDevice::mixSources` runs on the OS audio thread. Its scratch (`tmpBuf`) is sized ONCE in the constructor (`kMixScratchFrames`, 8192) and a larger request is mixed in chunks rather than growing the buffer — a heap allocation there can take an allocator lock and blow the buffer deadline. The same rule governs every `AudioSource::fillAudioBuffer`: **SID is the reference** (lock-free SPSC ring, `chipMutex` deliberately NOT taken, said so in its header), and `CassetteDevice` now follows it — `loadAudioStream` builds the `ma_decoder` OUTSIDE `audioStreamMutex` and swaps a `std::unique_ptr` under a short lock, `closeAudioStream` steals the pointer under the lock and runs `ma_decoder_uninit` outside it. It used to hold that mutex across `ma_decoder_init_file()` plus a frame count that can walk a whole MP3, so inserting a tape dropped audio for as long as the media was slow. **The decoder must stay heap-owned**: miniaudio's data-source base holds pointers into the object, so a by-value `ma_decoder` cannot be moved in after init. Note what can and cannot catch this class of bug — it is neither a lock-order inversion (`src/LockOrder.h` is blind to it) nor a data race (TSan is blind to it); it is purely how long a lock is held, so no CI job substitutes for reading the call path.
- **`~CassetteDevice()` is not `= default`** — a mounted stream tape owns a live `ma_decoder`, and only `ma_decoder_uninit` releases the backend's buffers and file handle. Destroying the owning pointer alone leaks them, which the nightly ASan job (`detect_leaks=1`) would report.
- **`logs/pom1.log` is the only log sink that outlives the process.** `src/Logger.h`'s `StreamLogger` writes to stdout — which goes nowhere on a Finder/Explorer double-click — and `RingBufferLogger` dies with the process, so before `FileLogger` a user had nothing to attach to a bug report, crash or not. It is the third child of the `TeeLogger` installed by `initDefaultTeeLogger()`: timestamped to the millisecond, flushed per entry (the entries that matter most are the last ones before a hang), rotated one deep at open, and a silent no-op when the file cannot be opened. **`pom1_macos_provision_user_data_dir()` must run BEFORE `initDefaultTeeLogger()`** — it is what `chdir`s into `~/Library/Application Support/POM1/`, and the sink resolves its relative path against the working directory; installed the other way round, a Finder launch wrote its log wherever Finder started us. Not installed under WASM (virtual FS, discarded on reload).
- **OOR (`ramKB < 64`)**: strict mode returns `$FF` and drops writes in `[ramKB*1024, $8000)` — matches real Apple-1 with no RAM board. Status bar: `OOR:N!` or `[strict]`.
- **`loadHexDump` has THREE parsers, picked by content — and they live in `src/MemoryImageLoader.{h,cpp}`, not in `Memory`.** `pom1::parseMemoryImage(content, fileName)` is **pure**: bytes and a name in (the name is never opened — it supplies the display string and the one `.tur` extension rule), a `MemoryImage` out carrying the writes as contiguous spans, the run address, a byte count and severity-tagged diagnostics. It touches no `mem[]`, no filesystem, no log sink, so `Memory::loadHexDump` is now *parse → decide → apply* and `memory_image_loader_smoke` reaches every dialect without an emulated machine. **Nothing partial ever escapes**: a rejected image drops every span, which the in-place loader could not promise — it wrote each Intel HEX record into RAM as it recognised it and only then discovered the record past `$FFFF`, and a file that established no address at all dumped its stray bytes into page zero before returning the error. Spans **are** the Memory Map zones (both are maximal contiguous runs). Default parser (legacy): joins every line into one string and recovers boundaries heuristically — comments (`//` `#` `;`, stripped inline, else `LDA`/`DEX` mnemonics parse as data), continuation lines, `R` suffix (run address), and **merged data+address** (`ED0300:` → data `ED` + addr `0300`, the artefact of that joining). A **TurboType `.TUR`** takes a **line-structured** parse, and an **Intel HEX** file takes `src/IntelHexFile.h`. Applying the result deliberately **bypasses the ROM write-protect** — a WOZMON dump is the user typing at the Monitor. **Hardening:** `kMaxMemoryImageBytes` = 8 MB (largest shipped dump ~100 KB; a full 64 KB image in WOZMON runs a few hundred KB) — `Memory::loadHexDump` checks the file's **size before reading it**, `parseMemoryImage` re-checks for every other caller, and both share `memoryImageTooLargeMessage()` so the two refusals cannot drift. Address tokens go through a **checked accumulator, never `strtol`**: `long` is 64-bit on macOS/Linux and 32-bit on Windows, so an over-wide token saturated differently on each — a TurboType line reading `100000000` truncated to `$0000` on the 64-bit hosts, putting the bytes that followed into **page zero**, while the 32-bit host clamped elsewhere and dropped them. The line-structured parser has no merged-token rule to fall back on, so it now skips and reports such a line; the joined parser keeps its documented merged data+address reading of the same token. Odd-length runs report the **address** of the first one, not just a count.
- **Why `.TUR` needs its own parser:** a turbo block puts the address on its own line and prefixes each 16-byte data line with `:` — the inverse of WOZMON's `AAAA:` suffix. Joined, every 32-digit data run is followed by the next line's `:`, so the legacy "hex token before `:` is an address" rule sliced off its last 4 digits as an address and **shredded the 15 Puzzle's $0300 block into 60+ bogus zones** ($18A9, $4159, $F460…). Keeping lines apart makes both dialects unambiguous and needs no merge hacks. `X` is a bare end-of-stream marker (it used to also swallow the `015ER` run line behind it, so POM1 jumped into the serial receiver at `$0100` instead). **Selected by the `.tur` EXTENSION *or* a lone `T` line** — the marker is optional in the wild (the same transfer is also published as plain address + `:data` blocks), and a marker-less file left to the legacy parser hits exactly the shredding above. Everything else still needs its `T`, so the ~100 bundled `.txt` dumps keep byte-identical legacy behaviour.
- **Intel HEX (`:LLAAAATT<data>CC`) is a second, unrelated `.hex` dialect** — `src/IntelHexFile.h`, pinned by **`intel_hex_smoke`**. Fed to the WOZMON parser it had no `AAAA:` address, so every digit (byte count, load address, record type, checksum) was written as **data** at whatever address was current — silent, same class as the old `.apl` fall-through. Detection is **structural, never extension-based** (`looksLikeIntelHex` validates the first record's count/type/checksum together), so an Intel HEX named `.txt` loads correctly and a WOZMON dump named `.hex` is untouched; no bundled dump even starts a line with `:`. Once the first record validates POM1 **commits**: a later bad checksum, an unknown record type, or a record past `$FFFF` (the type 02/04 base records are an x86 inheritance) **fails the load loudly** instead of falling back to the WOZMON parser, which would resume writing record headers into RAM. A type 03/05 start record is the Intel-HEX equivalent of WOZMON's trailing `AAAAR`; a missing type-01 EOF only warns.
- **A `.TUR` load is self-checking**: POM1 injects RAM directly, so the `$0100` receiver is written but never executed; the file's last run address is its **CRC-CCITT checker**, which re-verifies the injected image on the emulated 6502 and jumps to the program on match / prints `EE` on mismatch. `hex_dump_turbotype_smoke` runs a real `.TUR` (`tests/fixtures/15puzzle.tur`) and asserts the game's banner appears — no golden byte array needed.
- **Which extensions reach `loadHexDump` is `pom1::isHexDumpPath` in `src/HexDumpFile.h`** — `.txt` `.hex` `.apl` `.mon` `.tur`, one list, four call sites (`CliDispatcher::runLoad`, the Load/Save Memory native filters + the ImGui fallback browser's directory listing in `MainWindow_FileDialogs.cpp`, `Pom1BenchHost::targetForPath`). `.apl` is Uncle Bernie's canonical Apple-1 name for a WOZMON-keystroke file; before the list existed, `--load 0280:prog.apl` fell through to `loadBinary` and wrote the file's **ASCII text** into RAM with no error. Bundled programs keep their `*.apl.txt` double extension (plain-text tooling + pinned test paths). Pinned by `hex_dump_extension_smoke`. `CodeBench.cpp` repeats the extensions literally on purpose (portable module, no POM1 headers).
- **ACI TAPE OUT vs bundled cassette** — `cassettes/WOZ_talk.mp3` is preloaded only when the **POM1 Multiplexing Fantasy (2026)** preset is applied (last preset index); Integer-BASIC cassette presets load `BASIC.aci` instead. While a stream-mode tape is inserted, live `$C0xx` toggles (`$C030` chiptune in GEN2 *A-1-CrazyCycle*) stay silent because `CassetteDevice::fillAudioBuffer()` never mixes the pulse queue. DevBench Run auto-ejects on ACI presets without the Integer-BASIC program tape.
- macOS: `pom1_macos_provision_user_data_dir()` creates `~/Library/Application Support/POM1/` with symlinks for read-only dirs + seeded `sdcard/`/`cfcard/`/`ini/` then chdirs there. Refreshed each launch (handles Gatekeeper App Translocation + `/Applications` drag-installs).

## Testing

`ctest` from `build/` (native-only, opt-out `-DPOM1_ENABLE_TESTS=OFF`). Inventory in `tests/CMakeLists.txt`; `ctest -N` lists exact names. CMake never invokes `dev/codetank/Makefile`; those are developer-only build steps. Tests load whatever artefact lives under `software/`.

```bash
ctest                       # full suite (~5–30 s wall time; Klaus + TMS9918 tests dominate)
tools/coverage.py --gate    # per-module line+branch coverage (nightly CI job)
ctest -L emulator           # the release gate — green with no cc65 and no editors
ctest -L devtools           # editors, DevBench/cc65 pipeline, BASIC compilers
ctest --output-on-failure
ctest -R klaus -V
```

**Coverage is measured per MODULE, never as one percentage** (`-DPOM1_COVERAGE=ON` + `tools/coverage.py`, nightly `coverage` job in `ci.yml`). A single figure over the 44 500 measurable lines averages a cycle-exact 6502 against 14 400 lines of ImGui drawing no test binary links: it moves for the wrong reasons and is improved by testing whatever is easiest. Measured today — **cpu 93.3 %, parsers 93.6 %, topology 89.9 %, snapshot 88.9 %, memory 79.4 %, platform 60.7 %, devices 52.4 %, control 34.3 %, devtools 24.3 %, ui 3.9 % of 14 468 lines** (the `ui` row was 2.4 % before the decision-extraction chantier; the seven seams it produced are at 100 % of lines, and what is left uncovered there is the ~13 900 that draw). **The extracted seams stay in the `ui` module on purpose** — `MODULES` in the script lists them explicitly — because the row is meant to say how much of the UI layer's LOGIC is tested, and reclassifying those lines elsewhere would improve the figure by moving the work, which is the gaming a per-module table exists to prevent. **A `constexpr` seam needs runtime calls as well as `static_assert`s**: instrumentation cannot see a compile-time evaluation, so `ShortcutTable.h` read as 30 % covered while every one of its properties was in fact PROVED, more strongly than a runtime assert can (a static_assert cannot be skipped). `shortcut_table_smoke` now asserts each property twice — once folded, once through a `volatile` launder (and a function pointer for the no-argument overload) — which is what took that file to 100 %. Reach for the same trick in the next pure header, or its row will understate what it guarantees. Only the first four are GATED (`THRESHOLDS` in the script: 90/90/85/85, set just under what the suite measures, so they catch a module LOSING coverage — a branch arriving without its case); the rest are reported, because a floor under 2.4 % UI coverage would be a number pretending to be a promise. The `ui` row is the quantified version of TODO.md's chantier 3. `llvm-cov`/`llvm-profdata` must come from the clang that compiled the tree — a mismatch says only "unsupported coverage format version" — so the script resolves them by that compiler's major version.

**Windows reserves 1 MB of stack per thread; Linux and macOS give 8.** `CMakeLists.txt` raises MSVC's reserve to 8 MB (`/STACK:8388608`) because POM1 is written against the larger one and the gap is not theoretical: `sizeof(EmulationSnapshot)` is **260 KB** and `sizeof(EmulationController)` **261 KB**, so a test holding a controller and three snapshots by value is over the 1 MB line by arithmetic. Two tests died that way on Windows alone for five days — **with no output at all**, because the CRT discards a buffered stdout when the process dies, so `--output-on-failure` showed nothing and it read as an inexplicable segfault. The way to find this from a machine that is not the one crashing is `clang -Wframe-larger-than=32768` over the test sources: it printed 2 130 928 B and 801 344 B for the two that crashed and 267 824 B for the one that passed. Reach for it before believing a Windows-only crash is a logic bug.

**Two lanes, and every declared test carries exactly one of them** (`LABELS`,
assigned at the bottom of `tests/CMakeLists.txt` from the `POM1_DEVTOOLS_TESTS`
list). `emulator` (90 tests) is what an emulator release must pass, and it is
green on a machine with **no cc65** — the toolchain-dependent tests in it
(`lib_micro_tests`) skip with 77 rather than fail. `devtools` (28) is the
development environment's own lane: the editors, the DevBench/cc65 pipeline,
the BASIC compilers and their 6502 runtime. The rule for the list is
**subject**, not name: a test is `devtools` when it compiles a source from the
devtools set that `tools/check_architecture.py` guards, or drives cc65 —
`bench_basic_inject_smoke`, `bench_logo_inject_smoke`, `applesoft_*`,
`codetank_claudio_gate`, `lib_micro_tests` and the `dev/` assembly lints all
assert *emulator* behaviour and stay in the gate despite their names. **Absent
from the list means `emulator`**, deliberately: an unlabelled devtools test
lands in the release gate and turns it red on a cc65-less machine, where the
other default would drop a test out of the gate in silence. `ci.yml`'s Linux
job runs the two lanes as two steps — the same 118 tests, at no extra cost,
with a red step that names which product broke.

The transcendentals are feature-gated so they link only when used. Skips (77) without cc65.
- **`size_report_smoke`** — `tools/size_report.py` (ld65 map → per-region headroom incl. minus-the-C-stack, per-module byte table, `--why module` reference chains, `--min-headroom [REGION:]N` CI gate) **+ the DevBench archive-link model**: rebuilds the gen2c runtime `.lib` from `dev/bench/gen2c.json` (pins the spec's buildability), links a text-only program, asserts unused families are dead-stripped and the headroom math holds. Skips (77) without cl65+ar65.
- **`ehbasic_smoke`** — Lee Davison's Enhanced 6502 BASIC 2.22 at `$5000-$7FFF` (`roms/ehbasic.rom`, flashed into RAM, cold `5000R` / warm `5003R`). **The Apple-1 port is POM1's own** — none existed; upstream only ships a Kowalski-simulator stub with a fake ACIA — so `dev/ehbasic/src/` carries the PIA I/O and the entry stub while `basic.asm` stays untouched. There is therefore no published image to diff against and **running the interpreter IS the verification**: the test boots it, checks `PRINT 1/4` = `.25` and `PRINT SQR(2)` = `1.41421`, then types a `FOR` loop and runs it. It also asserts the string `DERIVED FROM EHBASIC` is still in the image — **that is a licence condition, not a style check** (EhBASIC requires it in any distributed binary; `dev/ehbasic/README.md` is the human-readable half). Rebuild with `dev/ehbasic/build_ehbasic.sh`.
- **`msbasic_smoke`** — Microsoft BASIC 6502 at `$E000` (`roms/msbasic.rom`, floating point, cold `E000R` / warm `E003R`). Boots the ROM on the emulated 6502, answers its two cold-start prompts and asserts `PRINT 1/4` yields `.25` — what no checksum can tell you. Also pins that `loadMsBasic` restores POM1's own Woz Monitor over the image's bundled copy (the file is a full 8 KB `$E000-$FFFF` EPROM image, kept intact so its sha256 still matches the published ROM) and that `unloadBasic` clears the FULL `$E000-$FEFF` window — MS BASIC is nearly twice Integer BASIC's size, so the old `$E000-$EFFF` clear left 3 KB of the previous interpreter behind when switching flavours. **The ROM is reproducible from public sources** — `dev/msbasic/build_msbasic.sh` rebuilds it from pinned mist64/msbasic + coopzone-dc overlay commits and asserts the hash; provenance, the four missing target-dispatch patches and the licence position are in `dev/msbasic/README.md`.
- **`measured_cpu_rate_smoke`** — the status bar's MEASURED clock rate (`EmulationController::getMeasuredCpuHz`) vs the pacer's target. Wall-clock based, loose bands; it separates "measured" from "target" and from the burst-rate bug (charging elapsed time only to slices that ran the CPU reads x1 as tens of MHz). Also pins that a parked CPU publishes 0 — the window only refreshes inside `runEmulationSlice`, which the park branch skips.
- **`lock_order_smoke`** — the mutex order (`stateMutex > keyboard.keyMutex > publisher.snapshotMutex`) is now ENFORCED, not just documented: `src/LockOrder.h` gives each lock a rank and asserts a thread only ever takes one strictly inside what it already holds. `PriorityMutex` carries the `State` rank; `keyMutex` and `snapshotMutex` are `pom1::RankedMutex<...>` (BasicLockable, so the six existing `lock_guard` sites only changed their template argument). Compiled out under `NDEBUG`, live in the test binaries (`-UNDEBUG`) and in Debug builds — and layout-identical either way, so no ABI hazard. The test **forks a child per inversion and reaps `SIGABRT`**, which is the point: a checker that never fires reads as coverage while providing none. It carries a control case for the same reason — a checker that aborted on *everything* would otherwise pass every assertion.
- **`doc_paths_sync`** — third guard of the `version_sync` / `imgui_pin_sync` family (`tools/check_doc_paths.py`): every source path the markdown cites in backticks must exist. 370 citations checked, resolved against the repo root, the citing document's own directory, `src/`, `dev/` and `dev/lib/` — those last three being the conventions the docs actually use. `CHANGELOG.md` is excluded whole (a changelog naming a file that has since moved is correct history, not drift), as are `EXTERNAL_ROOTS` (POM2, upstream demos, toolkit headers) and filename templates like `imgui_preset_NN.ini`. Replaces a manual pass — the git log already contains one that fixed 20 drifts by hand.
- **`action_pins_sync`** — fifth guard of the family (`tools/check_action_pins.py`): every `uses:` in `.github/workflows/` names a 40-hex commit SHA with the version it came from in a trailing `# vX.Y.Z` comment. `@v5` is not a version — it is a mutable pointer in someone else's repository, and these workflows carry the repo's secrets (`release.yml` builds, signs and publishes the downloads; `pages.yml` deploys the site). **Offline by construction**: it never asks GitHub whether a SHA exists, because a test that needs the network goes red on a train — it holds the SHAPE, and `.github/dependabot.yml` (monthly, grouped, rewrites SHA *and* comment together) holds the freshness. It also refuses one SHA commented as two different versions across files, which is a half-finished bump. Note `upload-artifact` is deliberately v4 on `ci.yml`/`pages.yml` and v5 on `release.yml`/`pi-borne.yml`: pinning is not upgrading.
- **`resource_probes_sync`** — fourth guard of the `version_sync` / `imgui_pin_sync` / `doc_paths_sync` family (`tools/check_resource_probes.py`): no POM1 source may spell its own `"x", "../x", "../../x"` walk. 241 files scanned, 5 allowlisted non-probe sites (MicroSD's guest-side traversal check, the four editors' "parent directory" browser row), each with its reason in the script. It replaces a review habit — the probes it removed disagreed on how far to climb and half of them had no exe-relative branch outside Windows — and it is verified in BOTH directions: reintroducing one probe fails the test.
- **`concurrent_frontends_smoke`** — the three production concurrency roles without ImGui or an audio backend. It gates what POM1 CONTROLS: `maxStateHoldNs` (100 ms; measured 18-68 ms) and `maxAudioCallbackNs` (50 ms; measured 7-33 µs), plus snapshot validity and the audio sample count. **`maxStateWaitNs` is a catastrophe bound (5 s = a hang), deliberately not a quality one.** At 500 ms it fired on a healthy GitHub Linux runner at 1.66 s while the max HOLD stayed at 16 ms — nobody held the lock too long, a waiter lost the scheduler — and on an idle 8-core Mac the same quantity already ranges 57-350 ms. It also does not detect what it was there for: disabling the `PriorityMutex` yield in `emulationLoop` and running eight times tripped 500 ms ONCE. What the yield actually buys is PROGRESS of the contending thread — topology swaps completed in the window, median ~117 with it against ~35 without, eight runs each; the distributions overlap on a single run (116 vs 45), so that is the measurement a future gate should be built on, not yet a threshold. Note the test had never once run on Linux CI: it arrived in the same commit that broke that build.
- **`d64_fuzz_smoke`** — hostile input against the 1541 disk-image reader, mutating a real formatted disk with files on it (random bytes almost never reach the traversal code). Invariants: mounting is decided by size alone, every traversal **terminates**, directory entries and file contents are bounded by the disk rather than by the numbers the disk contains, free blocks stay within the geometry, and reading leaves the image byte-identical. **It found both defects** `d64_parse_smoke` now pins — the counter-based chain walks and the unclamped BAM count. A 30 000-image campaign under ASan+UBSan is clean.
- **`snapshot_validate_smoke`** — the snapshot pre-flight (`pom1::outlineSnapshot` / `validateSnapshot` in `SnapshotIO.h`), pure: no `Memory`, no CPU, no file in the binary. Applying a snapshot writes **straight into the live machine, section by section**, so a file that went bad halfway left a HYBRID and reported a clean failure — truncating a real 116 933-byte snapshot to 200 bytes restored the CPU section, program counter and all, over RAM that was never replaced, and a PC pointing into a program that is not in memory is a machine that will run garbage. Rewind replays these same blobs. Seven sections pin the section walk, the magic/version gate (a future version is refused, never half-understood), truncation caught mid-header / mid-payload / at a boundary, a forged length checked against the bytes **remaining** (never `offset+length`, which wraps on wasm32), MEM's two legal lengths and nothing else, GEN2VID's event count bounded by the payload actually present (the count drives a `reserve()`), and that a rejected outline reports **no sections at all**.
- **`snapshot_fuzz_smoke`** — hostile input against that gate, enumerating **every** truncation of a realistic snapshot byte by byte (66 631 of them — the exact family that produced the hybrid machine, cheap enough to exhaust rather than sample) plus the usual mutation rounds aimed at the 32-bit length fields. Invariants: validate ⇒ outline ok, every section indexable inside the buffer, sections **tile** the file in order with no overlap and no unaccounted tail, every refusal explained, and determinism.
- **`pcm_file_smoke`** — the two cassette containers as pure functions (`PcmFile.h`, above), with the WAV/AIFF bytes built in the test rather than read from disk. Twelve sections: the signed/unsigned 8-bit split, 16/24/32-bit and float32, the channel mixdown, AIFF-C `sowt`/`fl32`, the 80-bit rate (including its absurd-value refusal), SSND's offset and a malformed one, COMM's smaller-wins rule, the wrap-safe chunk-size guard, the frame cap (exercised through a `maxFrames` parameter — the real cap is 172.8 M frames and crossing it for real would allocate the better part of a gigabyte inside a unit test), the file-size cap, and that unsupported widths are refused **before** any frame is decoded.
- **`pcm_file_fuzz_smoke`** — hostile input against those two parsers: the surface where POM1 reads a **binary** file a user picked, and where chunked-format length arithmetic goes wrong. Same dual shape as the memory-image fuzzer, with the mutator aimed at 32-bit length fields. Its invariants are the ones the consumer needs: a rejected parse is inert and explained, an accepted one has a rate the pulse decoder can divide by, the frame count is bounded by the cap **and** by the input (so no crafted header makes a small file allocate a large buffer), every sample is finite, truncation is never silent, and no input is accepted as both a WAV and an AIFF. **It found two real defects** — the unbounded WAV sample rate and the NaN/Inf passthrough, both now pinned as `pcm_file_smoke` §11-§12.
- **`memory_image_fuzz_smoke`** — hostile input against the loader, in two shapes from one source (`tests/memory_image_fuzz_test.cpp`). The default build is a **deterministic** driver (fixed seed, so a failure reproduces byte for byte): it replays a corpus of real dump shapes, mutates it toward the punctuation that steers the parser, and holds **every** result to the header's contract — 64 KB containment, `byteCount` agreeing with the spans, no writes on a rejected image, `zones()` matching span for span, output bounded by input (amplification is a DoS shape, not a parse), and an identical result on a re-parse (purity). `-DPOM1_FUZZERS=ON` puts the same checks behind `LLVMFuzzerTestOneInput` for the long ASan campaign — the deterministic driver is the **default** rather than the fallback because Apple clang ships no libFuzzer, so a fuzz-only gate would silently not run on macOS. A 60 000-input campaign under ASan+UBSan found no memory fault; the defect it did surface (the `strtol` platform split above) came from reading the code, which is worth knowing about what fuzzing does and does not buy here.
- **`hermetic_core_smoke`** — the exit criterion of the host-services work as an assertion: a core built for a test touches nothing it was not given. Measured before the work, a bare `Memory` took **205 ms**, opened a real audio device, bound `localhost:6502` and opened the 32 MB CF image — for every test binary in the suite. Three sections: an empty root finds nothing and *reports* the Woz Monitor fallback; **two cores coexist in one process** with no listening socket (where "failed to bind port 6502" used to appear), and `resetMemory()` opens none either; and an injected root that HAS a ROM is actually used (a distinguishable 256-byte image lands at `$FF00`). §4 closes the audio half: a core built on a `pom1::NullAudioService` talks to the service it was given, registers its cassette on it at activation (not at construction — the deck rides its own rail), and **hands every source back in `~Memory`**, which is what makes an injected service that outlives the machine safe. The 133 ms that item was blamed on the audio object turned out not to be it: measured in a test build, `AudioDevice(false)` costs **0.07 ms** and the first `pom1::SID` costs **~120 ms** (libresidfp's filter tables; 0.46 ms for every SID after it, per process). §5 closes that half in turn — **`Memory` no longer builds the SID chip at all** (`Memory::sidChip()`, below), so a bare core comes up in **0.3 ms** where it took 135 ms, and the section pins both halves: the construction budget (60 ms, with no "is the chip built?" accessor to assert on — `memory_public_methods` is frozen — so the observable is the one that mattered) and the functional half, that plugging the card builds the chip **and** registers it on the injected mixer.
- **`native_file_dialog_smoke`** — the Linux picker's WAIT, not its UI. POM1 links no GTK/Qt: it forks `zenity`/`kdialog` and reads the path off a pipe, on the render thread — so the blocking wait it used to do froze the window for as long as the dialog was up and GNOME reported POM1 as not responding. Testable without a desktop because the backend is just a child process: a fake `zenity` on `$PATH` (prepended, never replacing it — a replaced `$PATH` leaves the fake script with no `sleep`, and the "slow" child then answers instantly, silently defeating the test) stands in for the real one. Four sections: a slow picker is pumped *throughout* rather than once at the end, the pumped path still round-trips the child's answer, a cancel is still a clean `false`, and with no pump installed the old blocking wait still works. Linux-only — the Win32/Cocoa backends run their own modal loop and never fork.
- **`resource_locator_smoke`** — the search order as a value (`ResourceLocator.h`, above). Seven sections: roots consulted in order with first-hit-wins, a miss being an empty path rather than a guess, `findDirectory()` refusing a file, an absolute path returned unrewritten, `rootedAt()` seeing nothing outside its root, a non-existent root being skipped rather than fatal, and `defaultLocator()` deduplicating its roots and **following a chdir**.
- **`memory_image_loader_smoke`** — the three dialects as pure functions (`MemoryImageLoader.h`, above), no `Memory` and no file in the binary. Ten sections pin what each branch exists to prevent: zone merging (else `chess.txt` becomes one zone per 8-byte row), the 1-2 digit token before `:` staying **data** (else mandelbrot-65 et al. scatter across zero page), both merged-token branches, Intel HEX detected by **shape** with a WOZMON dump named `.hex` untouched, TurboType selected by extension **or** a lone `T` — including a pin on the shredding a marker-less `.tur` suffers under the legacy parser, so the selection rule cannot quietly widen — the bare `X` marker keeping its trailing run address, odd-nibble reporting, the 64 KB clamp, **twice** that a rejected image carries no writes, the checked address accumulator (both dialects), the odd-run location and the size cap at and past the limit.
- **`staged_card_configuration_smoke`** — the UI's card-configuration transaction (`StagedCardConfiguration.h`, above). Pins that an untouched transaction has nothing to commit (the BBS regression), that the first `stage()` seeds cards + board options from the live machine so an amend adds rather than replaces, that a wholesale `cards` assignment still wins (`applyMachineConfig`), that `clear()` preserves `mode`, and that `stage()` seeds once per transaction. Links nothing but the header — the point is that this decision is reachable without ImGui.
- **`layout_decisions_smoke`** — the layout and fullscreen ARBITRATION (`LayoutDecisions.h`, above), pure: no ImGui, no GLFW, no window manager in the binary — it links only `WindowGeometry.cpp`, and only so §4 can round-trip a decided geometry through the REAL sidecar writer and parser (a field can be decided correctly and then dropped by the format; `fullscreenMode` is exactly that shape, since it arrived after the legacy two-field form). Eight sections: the windowed rect is only ever sampled from a windowed frame, what gets persisted (kiosk exemption, macOS space, `GLFW_MAXIMIZED` inside one), all five restore branches, the round trip, a layout reset and its dropped `Apple 1 Screen` placement, forced-vs-consumed placements, the checkbox against AppKit's animated exit (latch, timeout, swallowed second click), and the OS window size including the Fantasy floor's deliberate absence on WASM. This is the test the six august-2026 fullscreen defects had nowhere to live in.
- **`preset_decisions_smoke`** — what applying a preset means (`PresetDecisions.h`, above), pure, but linking the **real** `MachinePresets.cpp`: the assertions are about the thirteen machines POM1 ships rather than about fixtures, which is what makes "the shipped table exercises every branch" assertable at all. Eight sections: the silicon bundle is all-or-nothing and exactly the two multiplexing profiles disarm it (`PLabFantasy` + `Pom1Fantasy` — **not** one, which is what the first draft of this test asserted and the table refuted), the preset path and the master button compose byte-identical bundles, the strict 8 KB ceiling, the ROM profile over all thirteen, the ROM INVENTORY agreeing with that profile branch by branch (the drift pin — two copies of one predicate is a Memory Map that can describe a machine other than the one running), which preset preloads which tape and which of them is DATA, the DevBench/banner predicates, and the cold-reset rule including its silicon exception on first apply.
- **`shortcut_table_smoke`** — the key bindings (`ShortcutTable.h`, above). Links **nothing at all**: the table is a header of `constexpr` data. Six sections: every row is usable (a null command is a key POM1 grabs and then drops), lookup discriminates on key AND mods (F5 vs Ctrl+F5 is a soft reset versus a power cycle that clears RAM), autorepeat belongs to the row, no chord is claimed twice, every `Command` is bound exactly once — and the CTRL+letter invariant is asserted **with a control case**: a hand-built table carrying `Ctrl+C` must be detected, and a `Ctrl+F5` one must not, because a predicate only ever asked about a table it passes reads as coverage while providing none (the same argument `lock_order_smoke` makes for its forked inversions).
- **`software_dir_rules_smoke`** — the source-directory → card mapping (`SoftwareDirRules.h`, above), both directions, linking nothing. Six sections: every rule usable and each card a picker default at most once, component matching under both separators and a mix (plus the four near-misses — prefix, suffix, no leading separator, no trailing one), every shipped directory resolving to its card while an ordinary program folder resolves to none, first-match-wins, the reverse direction including the ambiguous two-content-card machine that must leave the picker at the `software/` root, and the round trip from every picker default back through `matchPath`. Its companion is `bbs_autodial`, which drives the same rule end to end with a real modem and a real listener.
- **`bbs_autodial`** — the user-visible end of the same regression, offline (`tools/test_bbs_autodial.py`). Phase A reads both shipped `software/NET/bbs.*.txt` dumps as text and pins load address `$0280` + a NUL-terminated `ATDT <host>:23`. Phase B runs the SAME program with only its dial target rewritten to a listener the harness owns on `127.0.0.1`, and asserts the loader reports run `$0280`, the modem logs the dial, the emulated display shows the echoed `ATDT` and the modem's `CONNECT`, and the fake BBS accepted **exactly one** connection. No Internet is used or needed. It does NOT guard the staging decision — that lives in the UI, which no test binary links.
- **`extended_aci_smoke`** — Uncle Bernie's Extended ACI end to end: pins the `$C500` mapping / write-protect / ACI cascade *both ways*, then plays his own `cassettes/codebrk.aiff` through the real pulse path, types `C500R` + `RX RX`, and asserts Codebreaker autostarts (banner on `$D012`). Also the **only** gate on POM1's hand-rolled AIFF reader.

**CMake layers and test build model.** The dependency direction is materialised
as INTERFACE targets: `pom1_ui` → `pom1_app` → `pom1_devices` → `pom1_core`.
They initially carry usage requirements while source ownership migrates out of
the historical executable; this avoids changing runtime behaviour in a build
refactor. The 24 device sources every integration test needs
(`POM1_TEST_CORE_FILES`) are compiled once into the `pom1_test_devices` OBJECT
library declared in `tests/CMakeLists.txt`; its separate identity is deliberate:
tests inherit `-UNDEBUG`, while the Release app keeps `NDEBUG`. Sharing those
objects would silently disarm test assertions or arm them in production. The
common `pom1_add_smoke_test()` helper is used as test families migrate to the
smallest logical layer. A configure-time pass binds every executable consuming
`pom1_test_devices` to `pom1_devices` and aborts if object use and layer
declaration ever diverge. Before object sharing, a full build ran 1435
compilations, 1154 of them redundant (`TMS9918.cpp` compiled 53 times); it is
now about 355.

**Architecture trend guard.** `tools/check_architecture.py` (CTest
`architecture_check`) rejects any new direct include from the core/device set
toward ImGui or `MainWindow` and reports ceilings for `Memory`,
`EmulationController`, the `MainWindow_*` family, selected header fan-out and
sources outside `pom1_test_devices`. The checked-in
`tools/architecture_baseline.json` is a ratchet, not a target architecture:
lower a ceiling when a refactor improves it; never raise one merely to make CI
green. A deliberate new dependency requires an architectural review and an
explicit `allowed_reverse_dependencies` entry.

Two ratchets sit alongside it, both grandfathering what exists today rather
than describing a target:

- **The devtools boundary** — `DEVTOOLS_DIRS` / `DEVTOOLS_STEMS` name the
  development environment (`src/{bench,hgrpaint,hgrsprite,tmspaint,tmssprite,sfxbeep,sidtrack}/`,
  the `Pom1*Host` files, the BASIC compilers, `DbgFile`, `BenchDebugSession`),
  and every include of one of their headers from outside that set is an edge in
  `allowed_devtools_dependencies`. There are **17**, in four files, all
  `MainWindow_*` — that is what makes the `-DPOM1_DEVTOOLS=OFF` work bounded,
  and the ratchet is what keeps it bounded while it waits. A new edge fails; so
  does an edge left in the baseline after its last call site is gone, so the
  list can only shrink.
- **Frozen facades** — `memory_public_methods` (188) and
  `controller_public_methods` (201) count declarations at class scope in
  `Memory.h` / `EmulationController.h`. The count, not the line total, is the
  property that matters: a facade shrinks by losing methods, and the old
  line-based ceilings say nothing about how much a caller can ask of the
  object. `Memory` is **frozen** (TODO.md chantier 2) — no new public method,
  no new `Memory.h` include — and `EmulationController`'s per-card passthroughs
  come off one at a time as their last caller goes (chantier 4). The audio-seam
  work is what that distinction is for: it kept `memory_public_methods` at 188
  (the injected service arrived as a third defaulted constructor parameter, not
  an overload) while `memory_lines` went **3934 → 3965**, and those 31 lines ARE
  the seam — the owned/borrowed pair, the constructor branch and the destructor
  that unregisters sources. That is the only kind of raise a ceiling here takes:
  one that names what bought it — the lazy SID is the second (`memory_lines`
  3965 → 3990, `controller_lines` 3079 → 3089, `memory_public_methods`
  unmoved at 188: those 35 lines are `sidChip()`, its two `mutable` members
  and the controller's deliberate pre-lock warm-up).

New invariant tests follow `tests/peripheral_bus_smoke_test.cpp` — `<cassert>` + `add_test` suffices; GTest/Catch2 only once multi-threaded tests land.

**Manual telnet tests** in `tools/test_*_telnet.py`. `test_sdcard_subdir_navigation_telnet.py` pins SD CARD OS "commands only search `currentDirectory`" — run from repo root.

## Version string locations

**Single source of truth: the repo-root `VERSION` file.** To bump: edit `VERSION`, run `tools/set_version.sh` (syncs the static docs), rebuild. Never hardcode the version anywhere else.

- **C++** reads it via the generated `PomVersion.h` (`POM1_VERSION_STRING`) — CMake `configure_file`s `cmake/PomVersion.h.in` from `VERSION` into the build dir (on the global include path). Used by `src/main_imgui.cpp`, `src/MainWindow_Dialogs.cpp`, `src/Screen_ImGui.cpp`.
- **CMake** reads `VERSION` for `MACOSX_BUNDLE_BUNDLE_VERSION` / `MACOSX_BUNDLE_SHORT_VERSION_STRING`.
- **Packaging scripts** read `VERSION` at runtime (override via `POM1_VERSION` env, e.g. the release workflow's git tag): `package_macos_release.sh`, `package_windows_release.bat`, `packaging/linux/build_appimage.sh`.
- **Static docs** carry a literal `POM1 v<version>` that `tools/set_version.sh` rewrites and `tools/check_version_sync.sh` (ctest **`version_sync`**) guards: `README.md` (title), `build-wasm/shell.html` (3×: `<meta>`, `<title>`, `.sub` header), `packaging/windows/README.txt` (header).
